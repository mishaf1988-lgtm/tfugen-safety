# שני חשבונות Claude לסירוגין: הקמה וסנכרון

נכתב 28/10/2026. מיכאל: "רשום הוראות מעבר לחשבון אחר עם כל הידע", ואחר כך בשאלון: "אני עובר לשם שנגמרים הטוקנים, אני רוצה חיבור זהה עם אותם כלים ולבסוף סנכרון בין המערכות, לא יהיה בלבול אחרי שאני חוזר לחשבון פה". מחליף את ההחלטה מ-06/10/2026 ("חשבון Claude אחד"), ראה `DECISIONS.md`. הרשימה המלאה של כל מה שמחוץ ל-GitHub: `project-files/ACCOUNT-INVENTORY.md`.

## איך זה עובד

- **החשבון הראשי** (sviva@tapugan.co.il): כאן רצים כל הסוכנים המתוזמנים, ופה המשרד ומפת המערכת.
- **החשבון השני** (Gmail של מיכאל): לשיחות בלבד, כשהמכסה בראשי נגמרה. **לא מקימים בו סוכנים מתוזמנים**: כל סוכן רץ רק בחשבון אחד, אחרת כל הודעה מגיעה פעמיים.
- **מה משותף לשניהם לבד:** הקוד, ההוראות, ההחלטות, הלקחים, ה-handoff (GitHub); "מי עובד על מה" (`claim.sh`, במסד); האפליקציה, המסד, הוואטסאפ והמייל.
- **מה משותף רק אחרי הקמה:** המשרד ומפת המערכת (שיתוף עם הרשאת עריכה), והמפתח `ROUTINE_KEY` (אותו ערך בשתי הסביבות).

## הקמה חד-פעמית של החשבון השני (מיכאל)

1. **להיכנס לחשבון השני** ב-claude.ai.
2. **לחבר Connectors** (Settings > Connectors): GitHub, Supabase, Microsoft 365, Cloudflare Developer Platform, Claude Docs. **ב-Microsoft 365 להתחבר עם sviva@tapugan.co.il, לא עם ה-Gmail**: אחרת אין גישה למייל, ליומן ול-OneDrive של העבודה. ב-GitHub לאשר את שני המאגרים: `tfugen-safety` ו-`michael-skills`.
3. **להתקין את ה-skills:** ה-plugin מהמאגר `michael-skills` (ראה `project-files/claude-ai-skill/README.md`).
4. **סביבת ענן ל-Claude Code** (claude.ai/code > Environments), כמו בראשי:
   - משתנה סביבה `ROUTINE_KEY`: **אותו ערך כמו בראשי** (מיכאל, 28/10/2026: "בצע: אותו מפתח"). הערך לא ב-GitHub; Claude בראשי מציג אותו בשיחה להדבקה. לא להחליף אותו ב-Cloudflare: מפתח חדש מנתק את החשבון השני או את הראשי.
   - Network secret ל-`api.cloudflare.com` (מפתח API מ-Cloudflare, My Profile > API Tokens, הרשאת Pages).
   - גישת רשת: כמו בסביבה של הראשי.
5. **בחשבון הראשי, שיתוף** (מיכאל, 28/10/2026: "בצע: לשתף עם הרשאת עריכה"): לפתוח את המשרד (https://claude.ai/artifact/AmxFowGHYDqyhd1sE9qphi) ואת מפת המערכת (https://claude.ai/artifact/KTMVcoPJBva43nKRacSLkc), Share, להוסיף את כתובת ה-Gmail כעורך.
6. **שיחה ראשונה בחשבון השני** עם המאגר `mishaf1988-lgtm/tfugen-safety`, ולהדביק את ההודעה שבסוף הקובץ.

## סנכרון בכל מעבר בין החשבונות

**לפני שעוזבים חשבון** (גם כשהמכסה עומדת להיגמר): לכתוב לשיחה "עובר חשבון". Claude:
1. ממזג או דוחף כל עבודה פתוחה (שום דבר לא נשאר רק בשיחה).
2. כותב handoff בשורש עם "מה בודקים" ו"מה מחכה למיכאל" (skill `tfugen-sessions`).
3. משחרר את מה שתפס ב-`claim.sh`.

**כשנכנסים לחשבון** (הראשי או השני): הודעת הפתיחה הרגילה. השיחה מושכת את `main`, קוראת את ה-handoff האחרון, ובודקת `bash project-files/claim.sh --list` כדי לא לגעת במה ששיחה בחשבון האחר מחזיקה.

**מה עדיין יכול לבלבל:**
- שיחה שנשארה פתוחה בחשבון האחר ממשיכה לעבוד על ה-branch שלה. כלל: נכנסים לחשבון, ממשיכים רק מה-handoff, לא מתוך שיחה ישנה.
- הסוכנים המתוזמנים ממשיכים לרוץ בראשי גם כשמיכאל בחשבון השני; הם צורכים מהמכסה של הראשי. אם המכסה שם נגמרה לגמרי, גם הם נעצרים עד שהיא מתחדשת.
- בחשבון השני אין גישה ל-Cowork (תור המשימות במחשב) ולארטיפקטים שלא שותפו.
- סימן שהשיתוף (הקמה, צעד 5) עוד לא נעשה: `supervisor.py` דורש לפתוח את המשרד, וה-Artifact open עונה "No Artifact ... that the user can see" (כך קרה ב-28/10/2026 גם למשרד וגם למפה). ניסיון אחד מספיק למפקח; לא לפרסם משרד חדש, לכתוב למיכאל שצעד 5 חסר.

**איך זה נאכף:** `hebrew-prompt.py` מזהה "עובר חשבון" בהודעה של מיכאל ומוסיף לשיחה הוראה לפעול לפי הסעיף הזה (`hebrew-prompt-test.py`).
