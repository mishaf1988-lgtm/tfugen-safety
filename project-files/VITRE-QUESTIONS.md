# Vitre — שלוש שאלות לספק, ומה נעשה עם כל תשובה

**למה זה כאן:** מיכאל רוצה לבדוק אם אפשר לחבר את Tapugan Safety ל-Vitre, שכבר בתשלום בארגון. דף האינטגרציות של Vitre מציג **REST API פתוח + webhooks**, אבל דף שיווקי לא אומר מה כלול ברישיון בפועל. בלי התשובות האלה אי-אפשר להעריך אם יש כאן משהו — ואסור להתחיל לבנות.

**סטטוס (עודכן 2026-09-23, ערב):** שתי שאלות נענו בפועל, בלי לשאול את הספק. מיכאל פתח ב-Vitre את «מפתחות API ציבוריים» (`app.vitre.io/publicApiKeys`) ויצר מפתח בעצמו (22/09/2026, תוקף עד 22/12/2026). כלומר: **(1)** ה-API כלול ברישיון, **(2)** מנהל המערכת בארגון מנפיק את המפתח, במוצר.

מה שנלמד ממסך המפתחות (צילומים 23/09):
- **Vitre מנפיקה זוג**: «מפתח API ציבורי» + «מפתח סודי ל-API ציבורי». מבנה key + secret. לכן ב-Cloudflare יוגדרו **שני** secrets: `VITRE_API_KEY` ו-`VITRE_API_SECRET`.
- **אין בחירת הרשאות** ביצירת מפתח (רק שם + תאריך תפוגה). המפתח מקבל כנראה את הרשאות המשתמש שיצר אותו (מנהל מערכת), כלומר כתיבה כלולה. זה עונה על חצי משאלה (3), ומחייב שהמפתחות יישארו רק ב-secrets.
- **אין קישור לתיעוד בשום מקום בממשק** (מסך המפתחות, הגדרות, עזרה). מיכאל בדק.

עדיין פתוח: **(3)** האם התראות/SMS יוצאות על רשומות שנוצרו דרך ה-API, ו-**(4)** התיעוד: כתובת בסיס, אופן האימות (איך שולחים את הזוג: headers? Basic? חתימה?), והקריאה ליצירת משימה. **בלי (4) אין עבודת פיתוח**: ניחוש של פורמט אימות שורף שעות. המפתחות לא נשלחים בצ'אט ולא נכנסים לקוד; ייקראו רק מתוך `functions/api/*`, כמו `META_ACCESS_TOKEN` ו-`RESEND_KEY`.

## ההודעה — להעתיק ולשלוח לאיש הקשר ב-Vitre (או למנהל המערכת בארגון)

> שלום,
>
> אני מיכאל פרייליך, מנהל הבטיחות בתעשיות תפוגן. יצרנו ב-Vitre מפתח API ציבורי ומפתח סודי (מסך «מפתחות API ציבוריים»), לצורך חיבור למערכת הבטיחות הפנימית שלנו. יש לי שלוש שאלות:
>
> 1. איפה תיעוד ה-API? (כתובת בסיס, אופן האימות עם המפתח הציבורי והסודי, ורשימת הקריאות)
> 2. האם דרך ה-API אפשר ליצור משימה ולהקצות אותה לעובד?
> 3. האם על משימה שנוצרה דרך ה-API יוצאות אותן התראות (SMS / מייל) כמו על משימה שנוצרה ידנית בממשק? זו השאלה הכי חשובה לנו.
>
> תודה,
> מיכאל פרייליך
> מנהל בטיחות, תעשיות תפוגן

## מה נעשה עם כל תשובה

| התשובה | המשמעות |
|---|---|
| **API כלול + מפתח קריאה-בלבד זמין** | מתחילים בכיוון אחד ובטוח: מושכים מ-Vitre לתוך שלנו (למשל רשימת עובדים או משימות פתוחות) בלי לכתוב לשם כלום. סיכון אפס. |
| **API כלול + התראות יוצאות גם דרך API** | זה הפרס הגדול. אפשר ליצור משימה ב-Vitre מתוך דיווח נאמן בטיחות, וה-SMS של Vitre מחליף את ערוץ ההתראות שנזנח (ראה DECISIONS 2026-09-19 — הדחיפה בוואטסאפ בוטלה כי דורשת מספר עסקי בתשלום). |
| **API כלול אבל התראות לא יוצאות דרך API** | הערך יורד משמעותית. עדיין שווה לסנכרון נתונים, אבל **לא** כתחליף לערוץ התראות — ואת זה צריך לדעת לפני שבונים עליו. |
| **API בתוספת תשלום** | מיכאל כבר אמר על WhatsApp: "הארגון לא יממן את זה לבד". אותה שאלה תחזור כאן. **לא להתחיל לבנות לפני החלטת תקציב.** |
| **אין API / סגור** | סוגרים את הנושא ומעדכנים כאן. |

## מה לא לעשות לפני התשובות

- **לא** לבנות מודול אינטגרציה "על סמך" דף השיווק.
- **לא** להניח מבנה נתונים של Vitre בלי תיעוד רשמי.
- **לא** לשמור מפתח API בקוד — כשיגיע, הוא הולך ל-Cloudflare env כמו `META_ACCESS_TOKEN` ו-`RESEND_KEY`, ונגיש רק דרך `functions/api/*`.
