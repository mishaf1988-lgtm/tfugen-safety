# מדריך מאוחד ל-Coworker — הפעלת מערכת המיילים האוטומטית של Tapugan Safety

## רקע
המשתמשת (מנהלת הבטיחות בתפוגן, `sviva@tapugan.co.il`) רוצה לקבל מיילים אוטומטיים על משימות פתוחות, ציוד שעומד לפוג, NCRs פתוחים וכו׳ — מהחשבון Outlook שלה דרך Microsoft Graph API.

**הקוד מוכן ופרוס בייצור** ב-`tapugan-safety.pages.dev`. נשארה פעולה ידנית אחת ב-Azure Portal שאני (Claude Code) לא יכול לבצע, כי זה דורש כניסה לחשבון Microsoft של המשתמשת.

---

## 🎯 המשימה היחידה — הוספת Mail.Send לאפליקציית Azure (10 דקות)

### שלב 1: כניסה
- URL: **https://portal.azure.com**
- כניסה עם החשבון `sviva@tapugan.co.il` (או חשבון Microsoft של המשתמשת)

### שלב 2: מציאת האפליקציה
1. בחיפוש למעלה: **App registrations** → לחיצה על התוצאה
2. בלשונית **Owned applications** או **All applications** — למצוא את האפליקציה שיצרנו ל-Tapugan
3. שם האפליקציה: כנראה **"Tapugan Safety"** או דומה. אם לא ברור — לבקש מהמשתמשת את ה-**Application (client) ID** שמופיע באפליקציה (תפריט … → ☁️ חיבור OneDrive → "שלב 1: Azure App Client ID")

### שלב 3: הוספת ההרשאה
1. בתפריט הצד של האפליקציה: **API permissions**
2. ללחוץ על **+ Add a permission**
3. לבחור **Microsoft Graph**
4. לבחור **Delegated permissions** (לא Application permissions!)
5. בחיפוש: לחפש **Mail.Send**
6. לסמן את התיבה ליד **Mail.Send** ("Send mail as a user")
7. ללחוץ **Add permissions** למטה

### שלב 4: אישור (אם נדרש)
- אם רואים כפתור **"Grant admin consent for [Tenant Name]"** למעלה → ללחוץ עליו ולאשר
- אם הכפתור לא קיים או לא לחיץ → זה בסדר, אומר שהאישור הוא Self-consent וההרשאה כבר פעילה
- בעמודה **Status** ליד `Mail.Send` אמור להופיע סימן ירוק ✓ ו-"Granted for [Tenant]"

### שלב 5: דיווח חזרה
- 📷 צילום מסך של דף **API permissions** עם `Mail.Send` מסומן ✓
- או טקסט פשוט: "Mail.Send נוסף ויש Granted ירוק"

## ⚠️ מה אסור לעשות

- ❌ **לא לשנות** את ה-Client ID (חובה שיישאר זהה)
- ❌ **לא להוסיף** הרשאות אחרות שלא מבקשים (כמו Files.Read.All, User.Read.All וכו')
- ❌ **לא ליצור** אפליקציה חדשה — חובה להוסיף לאפליקציה הקיימת בלבד
- ❌ **לא ליצור** Client Secret — האפליקציה משתמשת ב-PKCE, לא צריך secret
- ❌ **לא להגדיר** redirect URIs חדשים

## 🛠️ מה המשתמשת תעשה לבד אחרי שתאשר ש-Mail.Send נוסף

### א. התחברות מחדש
1. לפתוח את `tapugan-safety.pages.dev`
2. תפריט … → ☁️ **חיבור OneDrive (סנכרון מסמכים)**
3. ללחוץ על **התנתק** (כפתור אדום)
4. ללחוץ על **☁️ התחבר / זהו חשבון אחר**
5. בחלון Microsoft שיפתח → תופיע שורה חדשה **"Send mail as you"** → לאשר
6. החלון ייסגר, OneDrive יחזור להיות מחובר

### ב. הגדרת תפקידים (לא חובה — אפשר אחר כך)
1. בתפריט החדש שיופיע "📧 דוזון מייל" — לחיצה על **⚙️ הגדרות מיילים**
2. ה-modal יציג 4 תפקידים מוגדרים מראש:
   - מנהל בטיחות (כבר עם `sviva@tapugan.co.il`)
   - מנהל טכני (ריק)
   - מהנדס מפעל (ריק)
   - מנהל איכות (ריק)
3. אפשר להוסיף מיילים לתפקידים שונים מתי שרוצים — כפתור **"+ הוסיפי כתובת"** לכל תפקיד.

### ג. בדיקה ראשונה
- במודל ההגדרות — בחירת כלל מה-dropdown + לחיצה על **📤 שלחי עכשיו**
- מייל אמור להגיע תוך דקה לכתובת sviva@tapugan.co.il
- או בלחיצה ישירה על **📧 שלח דוח לעצמי עכשיו** (השולח לכתובת המוגדרת במנהל בטיחות)

## 🆘 פתרון תקלות נפוצות

### "sendMail 401: Mail.Send"
**משמעות:** הרשאת Mail.Send לא הוסיפה או לא ניתן לה consent.
**פתרון:**
1. לחזור ל-Azure → API permissions → לוודא ש-`Mail.Send` מופיע עם Granted ✓
2. אם לא — לבצע שוב את שלב 3+4 לעיל
3. במקרה הזה — המשתמשת חייבת להתנתק ולהתחבר מחדש לקבלת token טרי

### "sendMail 403"
**משמעות:** החשבון לא מורשה לשלוח (נדיר — קורה ב-tenants עם מדיניות מחמירה).
**פתרון:** צריך admin של ה-Tenant שיבצע "Grant admin consent" אחרי הוספת ההרשאה.

### "Insufficient privileges to grant admin consent"
**משמעות:** המשתמשת לא admin ב-tenant.
**פתרון:** לדלג על "Grant admin consent" — ההרשאה תעבוד ברמת המשתמש בלבד (Self-consent at sign-in). הסימן ירוק לא יופיע ב-API permissions אבל יעבוד.

### "לא הצלחנו לזהות את המייל שלך"
**משמעות:** ה-API `/me` לא החזיר mail/userPrincipalName.
**פתרון:** המשתמשת צריכה להוסיף את `sviva@tapugan.co.il` ידנית במודל "הגדרות מיילים" → תפקיד "מנהל בטיחות".
