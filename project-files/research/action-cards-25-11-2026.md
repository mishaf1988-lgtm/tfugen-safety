# מחקר: סוכן שיש לו את הכלל ולא ניגש אליו ברגע הפעולה (25/11/2026)

מיכאל: "נחפש מקורות של אנשים שמספרים איך התמודדו עם הבעיה". סוכן מחקר, מקורות שנקראו (2 מאמרים: רק התקציר).

1. תיעוד hooks של Anthropic (code.claude.com/docs/en/hooks): PreToolUse מחזיר `additionalContext`; השדה `if` מסנן לפי כלי וארגומנטים; עד 10,000 תווים. הבסיס הטכני לכרטיס.
2. תיעוד memory (code.claude.com/docs/en/memory): CLAUDE.md הוא הקשר, לא אכיפה; rules לפי paths נטענים רק בנגיעה בקובץ. מכסה עריכת קבצים, לא מייל לאדם.
3. Vercel (vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals): ב-56% מהמקרים ה-skill לא הופעל; skill לבד 53%, עם הוראה מפורשת 79%, אינדקס דחוס תמיד בהקשר 100% (דחסו 40KB ל-8KB). ידע שתלוי בבחירת המודל לא נשלף.
4. Sasha Podles (dev.to): PreToolUse על Read/Edit/Write מזריק את RULES.md של החבילה לפי הנתיב. אותו דפוס, בלי "פעם בשיחה".
5. Mike Adolan (dev.to): UserPromptSubmit לפי מילים, הזרקה מחדש אחרי compaction, Stop hook; 0 הפרות ב-1,300 שיחות (דיווח עצמי).
6. arXiv 2604.20911: איסורים נשחקים בשיחה ארוכה (73% בתור 5, 33% בתור 16); הזרקה מחדש מחזירה ציות.
7. arXiv 2605.01771: המודל מבטיח לעקוב ולא עוקב; מזהים רק מלוג הקריאות לכלים.
8. Cursor rules: Always, Auto Attached לפי glob, Agent Requested, Manual. רק לפי קבצים.

## שינויים לתוכנית (נכנסים לבנייה)
א. הזרקה חוזרת אחרי compaction או אחרי N תורות, לא רק פעם אחת בשיחה (6, 5).
ב. כרטיסי "השלמה" ב-PostToolUse או ב-Stop: אחרי שמירת טופס, בדיקה בלוג הכלים שהמפתח עודכן (6, 7). מכסה השמטה, שכרטיס לפני הפעולה לא תופס.
ג. סינון בשדה `if`, כרטיס מתחת ל-500 תווים, ואינדקס דחוס של שורה לכל פעולה תמיד בהקשר כרשת ביטחון (1, 3).
