# סקירת מסך: מה לחפש גם בלי שמיכאל שאל

מיכאל, 02/10/2026: "צריך להסתכל וגם בלי שאני תמיד אומר, לראות את הליקויים ולייעל".
כל צילום = לעבור על כל הרשימה. ליקוי קטן: לתקן באותו PR; גדול: הצעה. בתשובה: מה נמצא.

## ברשימה (כל אחד נמצא על מסך אמיתי)

| מה רואים | מה לבדוק | נמצא |
|---|---|---|
| מקף ארוך, «», חצים בטקסט | תווי מקלדת בלבד (CLAUDE.md). מקפים: נאכף ב-`keyboard-only-test.js` על כל `index.html` | הודעות, אזהרת מחיקה, תאים ריקים |
| תאריך "מלא" בשדה באייפון | שדה ריק מציג את היום. לבדוק בקוד אם מתאפס (לקח 36) | יעד ב-NCR |
| תג "0 י" או "פג" על תאריך שאינו תפוגה | `eb` רק לתפוגה; תאריך רגיל `fd` | תאריך גילוי NCR |
| כפתור צבעוני בלי סמל | צבע טקסט = צבע רקע? (`btn-d` אדום + רקע אדום) | ✕ מחיקה |
| פקודה, שם פונקציה או JSON על המסך | מיכאל לא מפתח; צריך כפתור | `setDeletePassword` |
| חלון שלא ממלא את רוחב הטלפון | `max-width` inline על `.modal` | חלון מחיקה |
| סטטוס שלא מתאים לתאריך | "מתוכנן" בתאריך שעבר | ביקורת |
| טקסט שנכתב ונעלם | מי עוד כותב לשדה: טיוטה, שרשרת, AI (לקח 37) | תיאור NCR |
| "נשמר" בלי רשומה | `execute_sql` + יומני `edge_logs` (POST לטבלה) | NCR שלא נשמר |
| תשובת AI כללית | ה-prompt מקבל מספיק הקשר? | סיבת שורש |

## איך בודקים
- DB: `execute_sql` על הטבלה, ו-`query_logs` על `edge_logs` לפי `request.path` ו-`method` כדי לדעת אם השמירה בכלל יצאה מהטלפון.
- תהליך: playwright ברוחב 375, כמו ב-`aud-findings-test.js`.
- ליקוי שנמצא פעם שנייה: שורה כאן לא מספיקה, להוסיף בדיקה.

## הצעות לשדרוג בסוף כל משימה
