# Lessons

**לחפש לפי הרגע:** לפני מיזוג, כשמשהו נכשל, לפני כתיבה למקום משותף, לפני טענה, יעילות.

## הכללים של הקובץ הזה

1. **טעות שמתגלה, של Claude או של מיכאל = לקח חדש באותו PR של התיקון.** נאכף: PR שהכותרת
   שלו מתחילה ב-Fix / Hotfix / תיקון לא עובר את `tests` בלי שינוי בקובץ הזה, או שורה
   `בלי לקח: <סיבה>` בתיאור (`lessons-gate.py`).
2. **טעות שחזרה:** מעלים את `חזר:` ומוסיפים איך התגלתה. לקח שחזר עם `נאכף: טקסט` = להוסיף
   hook או בדיקה, או `נאכף: טקסט (אין דרך בקוד: <למה>)` (`lessons-format-test.py` אוכף).
3. **גיזום וארכיון:** לקח שנאכף בקוד ולא חזר מתקצר לשורה אחת: `**N. כותרת (תאריך).** הכלל: ...; נאכף: `בדיקה`; חזר: 0`, ועובר ל-`project-files/lessons-archive.md` (02/10/2026, אחרי שש גזימות ללקח אחד ויום של גיזומים חוזרים). המספור רציף בין שני הקבצים (`lessons-format-test.py`). לקח מהארכיון שחזר: מעלים `חזר:` ומחזירים אותו לכאן עם גוף מלא. תקרה 14KB כאן (נבדק): קובץ ארוך נקרא ברפרוף.
4. **מבנה כל לקח** (הבדיקה אוכפת): כותרת `**N. ... (DD/MM/YYYY, #PR).**`, ואז שורות
   `מה קרה:`, `הכלל:`, `נאכף:`, `חזר:`. המספרים לא משתנים (יש אליהם הפניות); חדש = המספר הבא.
5. אם אפשר לאכוף בקוד, להציע hook או בדיקה.

## רטרו בסוף משימה (01/10/2026)

כל PR נושא שורה `רטרו: <תשובה>` בתיאור (`lessons-gate.py` חוסם בלעדיה). שלוש שאלות:
1. מה נכשל בניסיון הראשון?
2. מה מיכאל תיקן או אמר "לא לזה התכוונתי"? **המקור הכי חשוב.**
3. מה לקח יותר סבבים ממה שצריך?
אין תשובה = `רטרו: אין`, ולא ממציאים. יש תשובה שהיא טעות = לקח חדש כאן באותו PR.
וגם שורת `skill:` (מה נלמד ובאיזה skill נכתב, או `אין`): skill `tfugen-learn`.
`project-files/METRICS.md` סופר את זה חודשית.
